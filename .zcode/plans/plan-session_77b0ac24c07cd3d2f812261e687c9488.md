Décisions retenues par défaut (questions restées sans réponse) : **socle complet** pour NES/PCE (registre, inspect, décodeur 6502/HuC6280, squelettes, matrice — pas de recompilation complète cette passe) ; **GB + SG-1000/GG/SMS** câblés d'abord sur les 3 nouveaux backends (MSX/PICO-8 en passe suivante, affichés honnêtement « non câblés » par la matrice) ; **`--target pc`** nouveau TargetId, `desktop` reste le harnais host inchangé ; **AKA supposée ESP32-S3 N16R8** (16 Mo flash, 8 Mo PSRAM octal, 320×240 SPI ST7789-like, SD, I2S), facts isolés dans `targets/consoles/aka/aka_hw.h`.

## Étape 1 — Socle « cibles » : faits matériel + matrice de capacités (le cœur de « active/désactive selon le hardware »)

Côté recompilateur, dans `recompiler/include/m0boy/system.h` + `recompiler/src/system.cpp` :

- `TargetId { desktop, meta, pokitto, espboy, pc, odroid, aka }` (+ `parse_target`, validation et aide `main.cpp`).
- Nouveau `constexpr std::array target_table` de `TargetFacts { name, ram_bytes, flash_app_bytes, psram_bytes, screen_cols, screen_rows, has_sd, description }` — single source des faits : meta 32K/240K/160×128/SD, pokitto 32+2+2K/228K/220×176/SD, espboy 80K/1M/128×128/pas SD, pc (illimité, SDL), odroid 320K SRAM+4M PSRAM/16M flash/320×240/SD, aka 512K SRAM+8M PSRAM/16M flash/320×240/SD.
- `SystemDescriptor` gagne `Requirements { min_ram_bytes, min_vram_bytes }` (empreinte RAM invité de l'implémentation runtime, pas la spec de la console d'origine). `codegen_targets` reste la liste des pipelines **câblés**. Nouveau `available_targets(system)` = câblé ∩ capacité-hardware ; `supports()` s'appuie dessus ; erreur claire (« nes exige X KiB de RAM invité, meta en a 32 ») quand le hardware ne suit pas.
- `--list-targets` (nouveau) imprime la table des faits ; `--list-systems` imprime la matrice effective.
- Réconcilier les incohérences actuelles : branche pico8 de `main.cpp` qui bypass `supports()` alors que le registre dit `{desktop,meta}` alors que le générateur accepte pokitto/espboy.
- Nouveau `recompiler/src/codegen/target_info.{h,cpp}` : table consommée par les 3 générateurs (répertoire console, macro `GBL_TARGET_*`, fichier VERSION, modèle de stockage SD/flash-beside-app/fichier-host, écran) — fin des échelles if/else triplées ; les octets émis restent identiques.
- Tests : `test_source_systems.cpp` (6→8 systèmes, 4→7 cibles, matrice asserts), `test_source_cli.py` (`--list-targets`, `--system nes|pce` acceptés, message d'incompatibilité matérielle).

## Étape 2 — Backend PC / SDL (`--target pc`, `targets/consoles/pc/`)

La « console » pc réutilise les frontends partagés (gb_main.cpp, sg_main.cpp…) avec les mêmes m0_* :

- `pc_lcd.c` (fenêtre SDL2, texture poussée par `m0_lcd_send_rows`, échelle entière, présent vsync), `pc_audio.c` (queue audio SDL — précédents `gbl_host.c GBL_SDL` et `sg_player.c`), `pc_clock.c` (steady clock, `m0_micros`), clavier → `M0_MB_*` (précédent : mapping clavier gbl_host), `m0_watchdog_feed` no-op.
- Stockage **sans nouveau code** : périphérique bloc `m0_sd_*` adossé à un fichier `sd.img` (image FAT brute) → `m0_fat.c`, `m0_card.h`, `m0_state.cpp`, streaming fonctionnent verbatim comme sur META ; ROM compilée comme aujourd'hui. `M0_SCREEN_ROWS` côté pc = résolution native du système (GB 144, SG 192, GG 144) portée par la config générée, l'écran pc n'impose rien.
- `sg_frontend.h`/`sg_menu.h`/`m0_pad.h`/`m0_target.h` : branches pc. Templates `CMakeLists.txt.in` (exécutable natif + find_package(SDL2)), `README.md.in`, `VERSION` (0.1.0) rendus par le mécanisme `@NAME@` existant.
- Générateurs : `GBL_TARGET_PC` dans l'émission de config des 3 générateurs, listes de copie pc, budget flash sans limite, marqueur `sg1000-project.txt` accepte pc.
- `tests/test_pc_target.py` : génération GB+SG pc, **build exécuté en CI** (SDL2 requise, comme test_pico8_e2e), run_hash precise == interp à travers le frontend pc, fumigène menu/états sous `SDL_VIDEODRIVER=dummy`. Premier backend « matériel » vérifiable sans console.

## Étape 3 — Noyau ESP32 mutualisé + ODROID-GO (`--target odroid`)

ODROID-GO originelle : ESP32-WROVER, 16 Mo flash, 4 Mo PSRAM, ILI9341 320×240 SPI, DAC interne 8 bits (GPIO25), d-pad/A/B/Start/Select, molette volume, slot microSD.

- `targets/common/consoles/esp32/` (partagé odroid+aka) : `esp32_lcd.cpp` (SPI maître + DMA, push de lignes, letterbox natif→320×240 via `m0_scale.h`), `esp32_audio.cpp` (DAC ou I2S selon board), `esp32_clock.cpp` (80/160/240 MHz), `esp32_sd.cpp` (hooks bus `m0_sd.h` sur SPI → m0_fat/m0_state/streaming identiques à META), cache ROM flash+PSRAM (`espboy_build.py`-style image `rom.bin` + `m0_cache`).
- `targets/consoles/odroid/` : `esp32_board.h` (pins, contrôleur, timings), `platformio.ini.in` (espressif32, board PlatformIO intégrée `odroid_esp32`, arduino), `odroid_build.py.in`/`odroid_size.py.in` (partitions 16 Mo : app+rom+saves, contrôle taille, `firmware.sym` pour gm0 plus tard), `README.md.in`, `VERSION`.
- Câblage : `m0_target.h`/`M0_PAD` odroid, table target_info, budget GB (`meta_emitter.cpp`), marqueurs générateurs ; `tests/test_odroid_target.py` sur le modèle `test_espboy_target.py` (propriété du projet, parité host, build réel si `ODROID_PIO` fourni, `pio run -d`). `compile.sh` + `tools/meta-compiler` : TARGET=odroid.

## Étape 5 — NES : socle

- CPU : `recompiler/src/cpu/m6502/decoder.cpp` + `include/m0boy/cpu/m6502/{decoder.h,encoding.h}` (décomposition aaabbbcc propre au 6502, rien de commun avec `encoding.h` 8080). Instruction légère façon Z80 : mnémonique, longueur, cycles (+pénalité page), Flow, mode d'adressage, lectures/écritures mémoire, opcodes non documentés signalés. `CpuId::m6502`, lib CMake `m0boy_cpu_6502`, tests dans `test_cpu_decoders.cpp` + `asm6502.py` (assembleur 2 passes, modèle `z80asm.py`) pour une ROM NROM synthétique.
- Système : `recompiler/src/system/nes/cartridge.cpp` (iNES 1.0 : NES\x1a, PRG/CHR, mapper flags6/7, mirroring, batterie), `inspect()` ; `SystemId::nes`, reset 0xFFFC, work_ram 2 K. Exigences : WRAM 2 K + VRAM 2 K + CHR RAM — tient partout en RAM, la contrainte est la flash (ROM 16 K–1 M → LZSS/streaming comme GB). Câblé : {desktop, pc, odroid, aka} — interpréteur d'abord sur cibles à RAM/CPU confortables ; meta/pokitto explicitement « plus tard » dans la matrice.
- Squelettes : `targets/nes/runtime/nes_gen.h` (contrat façon `sg_gen.h`) + noyau machine WIP, générateur qui refuse la génération native avec un message dédié tant que le pipeline n'existe pas, `--info`/`--disasm` fonctionnels.

## Étape 6 — PC Engine : socle

- CPU : `CpuId::huc6280`, `recompiler/src/cpu/huc6280/decoder.cpp` déléguant les opcodes communs au décodeur m6502 + extensions (TAM/TMA, TII/TIN/TIA/TDD, SAT/SAM, SET).
- Système : détection `.pce`, heuristique d'en-tête (128 octets magique / taille brute), `inspect()` minimal, `SystemId::pce`, work_ram 8 K. Exigences : 8 K WRAM + 32 K+ VRAM VDC → **exclut mécaniquement meta/pokitto (32 K) et espboy (80 K borderline)** : la matrice de capacité se démontre toute seule sur ce cas.
- Squelettes : `targets/pce/runtime/pce_gen.h` + VDC/VCE/PSG WIP, même gating générateur que NES.

0 → 1 (fondation) → 2 (pc, premier gain CI) → 3 (esp32 commun + odroid) → 4 (aka, incrémental) → 5 (nes) → 6 (pce) → 7. Chaque étape se termine tests verts et firmwares existants inchangés ; les étapes 5–6 n'ont pas de dépendance sur 2–4 au-delà de la matrice (peuvent être échangées si besoin).
